«Оценка временных характеристик выполнения запросов в объёмной базе данных PostgreSQL»
Вариант 20
==============================================================================

Задание на защиту
  1. Составить запрос на вычисление суммарной выручки от продажи товаров двух поставщиков с заданными именами.
  2. Выполнить запрос 1), когда в таблицах ПРОДАЖА, ТОВАР, ПОСТАВЩИК нет индексов (никаких).
     Зафиксировать время в минутах и в мс выполнения 5 запросов и выделить самое маленькое.
  3. Ввести индексы:
       1) ПРОДАЖА по полю товар - btree       (def20_продажа_товар)
       2) ТОВАР по полю код - hash            (def20_товар_код)
          ТОВАР по полю поставщик - hash      (def20_товар_поставщик)
       3) ПОСТАВЩИК по полю название - btree  (def20_поставщик_название)
     и выполнить запрос один раз - с фиксацией времени любым способом,
     и один раз командой EXPLAIN ANALYZE.

  Примечание. В таблице ПОСТАВЩИК поле наименования называется «название»
  (DATA/create_tables), индекс построен по нему. Пункт 2) задания «товар по полю код,
  поставщик (hash)» выполнен как два hash-индекса таблицы ТОВАР: по полю код и по
  полю-ссылке поставщик.

  Примечание. В задании 3 запрос выполняется 5 раз (минимальное время выделено) -
  требование «один раз с фиксацией времени» выполнено с запасом, чтобы сравнение с
  заданием 2 не зависело от разброса отдельного замера.

Среда выполнения
  Windows 11 Pro, PostgreSQL 18.6, psql 18.6; база sales (схема и данные ЛР1 из DATA,
  ./help db), таблица ПРОДАЖА увеличена до 2 000 000 записей (./help lr2 gen,
  табличное пространство lr2_tbs на диске D:). Запуск - из PowerShell в корне проекта.

Текст запроса (файл big_db_indexes/zashita/v20_query.sql):
SELECT 'ООО Турман' AS "поставщик 1", 'ЧП Загорье' AS "поставщик 2",
       sum(ПРОДАЖА.количество * ТОВАР.цена2) AS "суммарная выручка"
FROM ПРОДАЖА
    INNER JOIN ТОВАР     ON ТОВАР.код = ПРОДАЖА.товар

Сравнение и выводы
------------------------------------------------------------------------------
   условие                        |  время, мс  | время, мин
   без индексов, минимум из 5     |     433.285 | 0.007221
   с индексами, минимум из 5      |     432.277 | 0.007205
   EXPLAIN ANALYZE (с индексами)  |     546.344 | 0.009106   (Planning Time 0.418 мс)

1) Суммарная выручка поставщиков ООО Турман и ЧП Загорье составила 422355932.0000 ден. ед.
2) Время выполнения без индексов и со всеми индексами варианта практически одинаково
   (разница -0.2 %, в пределах разброса отдельных замеров). Проверка плана
   (plan_check.sql) в заданиях 2 и 3 показывает причину: ни один узел плана не читает
   таблицы через индекс - созданные индексы планировщик не использует. Условию
   соответствуют товары двух поставщиков из пяти (4 товара из 10, около 40 % строк
   ПРОДАЖА), поэтому читать ПРОДАЖА по индексу дороже, чем последовательно: выбран
   Parallel Seq Scan по ПРОДАЖА и Hash Join с маленькой хеш-таблицей отобранных товаров.
   Справочники занимают одну страницу, и для них Seq Scan тоже дешевле индекса.
3) EXPLAIN ANALYZE показывает время несколько больше, чем обычное выполнение: при ANALYZE
   замеряется время каждого узла плана (накладные расходы на таймеры).
4) Индексы ускорили бы запрос при избирательном условии (малой доле строк ПРОДАЖА),
   например при отборе одного редкого товара; для данного задания они не дают выигрыша,
   но увеличивают размер базы и время вставки строк в ПРОДАЖА.
